# Plan: User-submitted text and model output are logged on every request; exception text returned to clients (issue #5)

Risk tier: High. Forced High: the change is a security and privacy control (what personal data reaches the Modal logs). It also alters existing behavior, and the Modal containers themselves cannot be exercised in CI (no GPU, torch, transformers or Modal credentials). Plan approved by the orchestrator on the user's behalf.

Domain skills:
- superpowers:test-driven-development: invoke.
- python-fastapi: not applicable because `verse_api` keeps its body and response handling; only `handle_verse_request` and `match_verse` change.
- context7-plugin:docs: not applicable because the only Modal API used newly is passing a keyword argument to `.remote(...)` and `Image.env(...)`, both already used or standard.
- django, django-ninja-api, expo, react, frontend skills: not applicable because the repo is a single Modal Python app.

## Acceptance criteria

1. With default settings (no `WWJD_LOG_FULL_TEXT=1`), neither the user-submitted text nor the model output (nor the full prompt, which contains the text) appears in any log record emitted by `handle_verse_request`, `match_verse`'s logging helper, or the exception logging, on the success, `422`, `502` (parse failure) and `500` (exception) paths. This includes exception messages: an exception whose message (or a chained `__cause__`/`__context__` message) contains the user text must not have that message logged.
2. No exception message or stack detail is returned in HTTP responses. The `500` and `502` bodies are exactly `{"error": <fixed message>, "id": <32 hex>}` (already true since #3); a test proves no exception text and no raw model output reach the body, with the flag off and with it on.
3. Every `print` call is removed from `wwjd_bot_modal.py`; logging goes through one module-level logger, `logging.getLogger("wwjd_bot")`, which emits at `INFO` and above.
4. Default logs carry metadata only: the request id, the input length, the generation time and output length (from `match_verse`), the HTTP status outcome, and for a `502` a fixed reason category (`not_dict`, `match_error`, `invalid_fields`). For an exception: the exception type names (including chained ones) and the traceback frames as file, line and function name only, no source lines, no messages, no locals.
5. When `WWJD_LOG_FULL_TEXT=1` is set, the full user text, the full prompt, the model output and the full exception (via `logger.exception`) are logged. Any other value, or unset, means off. The flag is read at call time, and when it is set in the shell that runs `modal serve` or `modal deploy`, it is baked into the image env so both containers see it.
6. The request id generated by `handle_verse_request` is passed to `match` as the keyword argument `request_id`, and `match_verse(text, request_id=None)` logs with it, so logs from both containers correlate. `match_verse` accepts only a 32 character lowercase hex id; anything else (including `None`) is replaced by a fresh one.
7. An exception inside `match_verse` is logged there with the safe format of criterion 4, and `match_verse` then raises a new `MatchVerseError` whose message holds only the request id, raised outside the `except` block so it has no `__cause__` or `__context__`. Modal's own logging of the failed call and the error that reaches `verse_api` therefore carry no user text.
8. `README.md` has a "Logging and data handling" section describing what is logged by default, the debug flag, how to enable it, and that it is off by default; the API contract text about ids in the logs is updated.
9. The CI gate (`ruff check .`, `pytest`, the import check) passes.

## Design

All in `wwjd_bot_modal.py` (the app is one file by design; see README).

### Logger

```python
import logging
import traceback

LOG_FULL_TEXT_ENV = "WWJD_LOG_FULL_TEXT"
logger = logging.getLogger("wwjd_bot")


def _configure_logger() -> None:
    if not logger.handlers:
        handler = logging.StreamHandler()
        handler.setFormatter(logging.Formatter("%(levelname)s %(name)s: %(message)s"))
        logger.addHandler(handler)
    logger.setLevel(logging.INFO)


_configure_logger()
```

`propagate` stays `True` so pytest's `caplog` (a root handler) captures records. The `if not logger.handlers` guard keeps the tests' repeated module re-imports from stacking handlers. The root logger has no handler in a Modal container by default, so lines are not duplicated.

```python
def _log_full_text() -> bool:
    return os.environ.get(LOG_FULL_TEXT_ENV) == "1"
```

Read at every call, so tests use `monkeypatch.setenv`/`delenv`.

### Image env for the flag

Keep the existing `.env({"HF_HOME": MODEL_DIR})` call exactly as is (`tests/test_image_pins.py` checks it by AST). After the `image = (...)` assignment add:

```python
def _full_text_image_env() -> dict:
    return {LOG_FULL_TEXT_ENV: "1"} if _log_full_text() else {}


if _full_text_image_env():
    image = image.env(_full_text_image_env())
```

So the default image definition is unchanged, and `WWJD_LOG_FULL_TEXT=1 modal serve wwjd_bot_modal.py` (or `deploy`) turns it on in both containers. In the container the variable is then set from the image env, so the re-import there builds the same image definition.

### Request id normalization

```python
_REQUEST_ID = re.compile(r"[0-9a-f]{32}")


def _normalize_request_id(request_id) -> str:
    if isinstance(request_id, str) and _REQUEST_ID.fullmatch(request_id):
        return request_id
    return uuid.uuid4().hex
```

### Safe exception logging

```python
def _exception_types(exc: BaseException) -> str:
    # Type names of exc and its chained causes/contexts, outermost first, cycle safe.
    names, seen = [], set()
    while exc is not None and id(exc) not in seen:
        seen.add(id(exc))
        names.append(f"{type(exc).__module__}.{type(exc).__qualname__}")
        exc = exc.__cause__ or exc.__context__
    return " <- ".join(names)


def _traceback_frames(exc: BaseException) -> str:
    # File, line and function only: no source lines, messages or locals.
    return "\n".join(
        f'  File "{frame.filename}", line {frame.lineno}, in {frame.name}'
        for frame in traceback.extract_tb(exc.__traceback__)
    )


def _log_exception(request_id: str, where: str, exc: BaseException) -> None:
    if _log_full_text():
        logger.error("[%s] %s failed", request_id, where, exc_info=exc)
        return
    logger.error(
        "[%s] %s failed: %s (message withheld; set %s=1 to log it)\nTraceback (most recent call last):\n%s",
        request_id, where, _exception_types(exc), LOG_FULL_TEXT_ENV, _traceback_frames(exc),
    )
```

Why not `logger.exception` by default: the issue recommends it, but its output ends with `str(exc)`, and exception messages from inside `match_verse` (tokenizer, transformers, Modal) can embed the input. Type names and frame locations cannot. Frames are rendered without their source lines so nothing but code locations is printed. With the flag on, `exc_info=exc` gives the full standard traceback.

### `handle_verse_request(text, match)`

Signature unchanged. Behavior:

1. `request_id = uuid.uuid4().hex`.
2. Invalid text: `logger.info("[%s] rejected: status=422 reason=empty_text", request_id)` and return the `422` body as today. (No length: the value may not be a string.)
3. `logger.info("[%s] request: input_length=%d", request_id, len(text))`; if `_log_full_text()`: `logger.info("[%s] input text: %r", request_id, text)`.
4. `result = match(text, request_id=request_id)` inside the existing `try`/`except Exception` (keep its `# noqa: BLE001` comment). On exception: `_log_exception(request_id, "match_verse", e)`, return the `500` body.
5. Reason categories replace the free-form reason strings: not a dict -> `not_dict`; has an `error` key -> `match_error`; fields missing, empty or not strings -> `invalid_fields`. Log `logger.warning("[%s] unparseable model output: status=502 reason=%s", request_id, reason)`. If `_log_full_text()` and the result is a dict whose `raw_output` is a string, also `logger.info("[%s] raw model output: %r", request_id, result["raw_output"])`. Return the `502` body.
6. Success: `logger.info("[%s] done: status=200", request_id)` and return the `200` body as today.

`verse_api` is unchanged: it still passes `match_verse.remote`, which now receives `request_id=` as a keyword.

### `match_verse(text: str, request_id: str | None = None)`

```python
class MatchVerseError(RuntimeError):
    """Raised by match_verse in place of any failure; carries only the request id."""


def _run_guarded(request_id: str, func, *args):
    try:
        return func(*args)
    except Exception as e:  # noqa: BLE001 log safely, then re-raise without the message
        _log_exception(request_id, "match_verse", e)
    raise MatchVerseError(f"match_verse failed for request {request_id}")
```

Raising after the `except` block (not inside it) leaves `__context__` empty. `match_verse` becomes:

```python
def match_verse(text: str, request_id: str | None = None):
    request_id = _normalize_request_id(request_id)
    return _run_guarded(request_id, _generate_verse, text, request_id)
```

and the current body (imports, token check, model load, generation) moves unchanged into a module-level `_generate_verse(text, request_id)`, except the five `print` lines, which become one call:

```python
return _log_generation(request_id, text, prompt, generated_text, elapsed_time, model_name)
```

```python
def _log_generation(request_id, text, prompt, generated_text, elapsed_time, model_name) -> dict:
    result = parse_model_output(generated_text, model_name, elapsed_time)
    logger.info(
        "[%s] generated: input_length=%d output_length=%d generation_time=%.2fs parse=%s",
        request_id, len(text), len(generated_text), elapsed_time,
        "parse_failed" if "error" in result else "ok",
    )
    if _log_full_text():
        logger.info("[%s] prompt sent:\n%s", request_id, prompt)
        logger.info("[%s] model output:\n%s", request_id, generated_text)
    return result
```

The token check's `RuntimeError` is still raised inside `_generate_verse`, so it is logged (type plus frames) and surfaces as `MatchVerseError`. The return value of `match_verse` is unchanged, including `raw_output` on a parse failure, which `handle_verse_request` never sends to the client.

## Risks

- `caplog` capture depends on `propagate=True`; a `StreamHandler` on our logger also writes to stderr in tests, harmless.
- Modal may also print uncaught exceptions from `match_verse` with their message; criterion 7 handles that by never letting the original exception leave `match_verse`.
- Modal transports `MatchVerseError` to `verse_api` either as that type or wrapped; either way `handle_verse_request` catches `Exception` and logs only type names.
- Changing what `match` is called with breaks any external caller of `handle_verse_request` that passes a one-argument callable; the only production caller is `verse_api`, which passes `match_verse.remote`.
- Riskiest step: moving the `match_verse` body into `_generate_verse`; keep it a pure move apart from the logging call so model behavior does not change. It cannot be run in CI.
- Chosen not to do: no structured/JSON log format, no log level env var, no change to what `match_verse` returns, no change to the extension (its privacy notice lives in GeoBradDev/WWJC_ChromeExtension and needs a matching note, said in the PR).

## Proof

All tests use a sentinel user text (for example `"SENTINEL-USER-TEXT jane@example.com"`) and a sentinel model output, and assert on `caplog.text` plus every record's `getMessage()` and formatted `exc_text`, so a message in either place counts. Fakes raise prebuilt exceptions so no frame's source line contains a sentinel.

- Criterion 1: default flag, `handle_verse_request` success, `422`, `502` (`{"error": "parse_failed", "raw_output": <sentinel output>}`), and `500` (an exception whose message contains the user text, with a chained `__cause__` whose message contains the output) emit no sentinel in logs; `_log_generation` with the flag off logs no prompt or output; `_run_guarded` with a failing function logs no sentinel.
- Criterion 2: on `500` and `502`, flag off and on, `repr(body)` contains no sentinel and no exception text, and `set(body) == {"error", "id"}`.
- Criterion 3: an AST test that `wwjd_bot_modal.py` contains no call to `print`, and `module.logger.name == "wwjd_bot"`.
- Criterion 4: default logs contain the request id, `input_length=<n>`, `status=...`, `reason=match_error|not_dict|invalid_fields`, the exception type names (outer and chained), `Traceback (most recent call last)` and the raising function's name; `_log_generation` logs `generation_time=1.23s`, `output_length=<n>` and `parse=ok|parse_failed`.
- Criterion 5: with `WWJD_LOG_FULL_TEXT=1` the user text, prompt, model output, raw output on `502`, and exception message appear; with `0`, `true` and empty string they do not. `_full_text_image_env()` is `{}` by default and `{"WWJD_LOG_FULL_TEXT": "1"}` with the flag.
- Criterion 6: the `request_id` the fake `match` receives equals the `id` in the `500` and `502` bodies and appears in the logs; `_normalize_request_id` keeps a valid id and replaces `None`, `""`, uppercase hex, and the user text.
- Criterion 7: `_run_guarded` re-raises `MatchVerseError` whose `str` contains only the request id and no sentinel, with `__cause__ is None` and `__context__ is None`; a successful function's return value passes through; `match_verse`'s raw function (`inspect.unwrap(app_module.match_verse.get_raw_f())` or the attribute the existing tests use for `verse_api`) accepts `request_id` with default `None`.
- Criterion 8: README review.
- Criterion 9: gate output.

Live drive (tier High, no Modal): a Python script in the scratch directory imports the module, configures nothing extra, and calls `handle_verse_request` with fakes for success, `422`, `502` and `500` (exception message containing the text), then `_run_guarded` with a failing function and `_log_generation`, first with the flag unset and then with `WWJD_LOG_FULL_TEXT=1`; it shows the real stderr log lines and the response bodies for each, and that the sentinel appears only in the flag-on run.
